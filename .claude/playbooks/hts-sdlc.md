# HTS SDLC — every change, no exceptions

The fleet-wide SDLC skeleton lives in the workbench (`~/.claude/playbooks/sdlc.md`).
This file is the **HTS-specific** overlay: validation gates, branch rules, and the
audit expectation for repos in the `hourtimesheet` org.

## The loop
1. **Branch** — `git checkout -b feat/<desc>` (or `fix/`, `bugfix/`, `chore/`,
   `docs/`, `hotfix/`). NEVER commit to the default branch. The default branch
   varies per repo (`main` vs `master`) — resolve it, never assume:
   `git symbolic-ref --short refs/remotes/origin/HEAD` → e.g. `origin/master`.
2. **Code** — smallest change that solves the problem; match surrounding style.
3. **Test** — add/extend tests for the change. Test framework is archetype-specific
   (JUnit 5 for Spring, Playwright/Cucumber for e2e, none for bare lambdas — see the
   archetype playbook). If the repo has **no test harness**, say so in the PR and add
   at least a smoke check (`node --check`, `npx serverless package`, `./gradlew compileJava`).
4. **Validate** — run the repo's validation gate (see `CLAUDE.md` → Validation gate).
5. **Commit** — descriptive message; reference the tracking issue (`Updates #<n>`)
   or the work issue (`Closes #<n>`). End commit messages with the Co-Authored-By
   trailer if generated by an agent.
6. **PR** — `gh pr create` with summary, context, test plan. Title framing per the
   workbench `titles.md` playbook.
7. **Audit** — for non-trivial changes, run the ensemble audit (`project-manager`
   agent → 7-dimension unanimous PASS). Fix all findings before merge.
8. **Deploy** — only after PR + green CI. Deploy procedure is archetype-specific
   (see the archetype playbook). Agents NEVER deploy production unilaterally.

## Validation gates by archetype (there is NO single org-wide command)
- **Spring/Gradle service or lib**: `./gradlew clean build` (compile + JUnit + Checkstyle)
- **Spring Cloud Function lambda**: `./gradlew clean build` then `./gradlew shadowJar`/`bootJar`
- **Serverless Node lambda**: `node --check handler.js` (+ every `*.js`); if a
  `package.json` with real tests exists, `npm ci && npm test`; `npx serverless package`
  validates the deploy bundle without deploying.
- **Express Node app**: `npm ci && node --check server.js && npm test` (note many
  HTS Node apps stub `test`; treat a stubbed test script as "no tests").
- **Angular/Ionic mobile**: `npm ci && npm run lint && npm test -- --watch=false --browsers=ChromeHeadless && npm run build`
- **Groovy/Jenkins library**: lint via the repo's GitHub Action (`ci.yaml`) /
  `npx @jenkins-cli/...` not available — rely on Jenkins Pipeline Unit if present.

## Hard rules (HTS)
- No secrets in code, `.env` committed to git, SSM plaintext that should be
  SecureString, or CI logs. Secret store: AWS Secrets Manager (acct 517311508324,
  `--profile lmntl`); Jasypt for Spring property encryption; SSM SecureString for
  lambda config. See `credentials.md`.
- DCAA timesheet records are append-only / audit-logged — never silently mutate or
  delete time-entry history.
- Tenant/company scoping: queries against `hourtimesheet`/`payroll` Mongo
  collections must be scoped by company — never return cross-company data.
